Sổ tay Git

Các lệnh cốt lõi cần nắm khi làm việc với Git, và cách xử lý conflict thực tế khi dùng merge, rebase, cherry-pick, pull.

~/firmware-project (main) 
$ git merge feature/uart-driver
Auto-merging drivers/uart.c
CONFLICT (content): Merge conflict in drivers/uart.c
Automatic merge failed; fix conflicts and then commit the result.

Cấu hình & khởi tạo

Nhóm lệnh dùng một lần khi bắt đầu với một repo hoặc một máy mới.

LệnhTuỳ chọn thường dùngMô tả
git init--bareKhởi tạo repo Git mới trong thư mục hiện tại. --bare dùng khi tạo repo chỉ để làm remote, không có working directory.
git clone <url>--depth 1--branch <name>Sao chép một repo về máy. --depth 1 chỉ lấy commit mới nhất (shallow clone), nhẹ hơn cho repo lớn hoặc CI.
git config--global--listThiết lập danh tính commit (user.name, user.email), editor mặc định, hoặc alias cho lệnh hay dùng.
git config --global init.defaultBranch main–Đặt tên nhánh mặc định mỗi khi chạy git init.

Staging & commit

Vòng lặp hằng ngày: xem thay đổi, đưa vào staging area, rồi commit.

LệnhTuỳ chọn thường dùngMô tả
git status-sXem file nào đã thay đổi, đã staged, hay chưa được theo dõi (untracked).
git add <file>-p-AĐưa thay đổi vào staging area. -p cho chọn từng phần (hunk) thay vì cả file.
git diff--stagedXem nội dung thay đổi. Mặc định là phần chưa staged; thêm --staged để xem phần đã staged, chưa commit.
git commit -m "..."--amend-aTạo commit từ staging area. --amend sửa lại commit gần nhất — chỉ dùng khi commit đó chưa push lên chỗ dùng chung.
git clean -fd-nXoá file untracked khỏi working directory. Luôn chạy -n (dry-run) trước để xem trước sẽ xoá gì.

Nhánh (branching)

Tách nhánh để làm việc độc lập, rồi gộp lại bằng merge hoặc rebase.

LệnhTuỳ chọn thường dùngMô tả
git branch-a-d-DLiệt kê hoặc xoá nhánh. -a xem cả nhánh remote, -D xoá cưỡng bức nhánh chưa merge.
git switch <branch>-c <new>Chuyển sang nhánh khác. -c tạo nhánh mới rồi chuyển sang luôn.
git checkout <branch>-b <new>Lệnh cũ hơn, làm cả việc của switch lẫn restore — vẫn rất phổ biến trong thực tế.
git merge <branch>--no-ff--abortGộp nhánh khác vào nhánh hiện tại. --no-ff luôn tạo merge commit dù có thể fast-forward.
git rebase <branch>-i--abort--continueĐặt lại các commit của nhánh hiện tại lên trên <branch>, giữ lịch sử thẳng, dễ đọc.

Remote

Đồng bộ giữa repo local và server (GitHub, GitLab, hoặc server nội bộ).

LệnhTuỳ chọn thường dùngMô tả
git remote -vaddremoveXem hoặc quản lý danh sách remote đang trỏ tới.
git fetch--all--pruneLấy dữ liệu mới nhất từ remote về — không tự động gộp vào working directory.
git pull--rebase--ff-onlyTương đương git fetch rồi git merge (mặc định), hoặc rồi rebase nếu thêm --rebase.
git push-u--force-with-leaseĐẩy commit lên remote. Khi cần ghi đè lịch sử, ưu tiên --force-with-lease thay vì --force vì nó kiểm tra remote chưa bị người khác cập nhật thêm.

Xem lịch sử

LệnhTuỳ chọn thường dùngMô tả
git log--oneline--graph--allXem lịch sử commit. Kết hợp cả ba cờ này cho cái nhìn dạng cây, rất trực quan khi có nhiều nhánh.
git show <commit>–Xem chi tiết thay đổi của một commit cụ thể.
git blame <file>-L <start>,<end>Xem từng dòng trong file do commit nào, ai sửa, lúc nào.
git diff <c1> <c2>–So sánh thay đổi giữa hai commit hoặc hai nhánh bất kỳ.

Hoàn tác thay đổi

LệnhTuỳ chọn thường dùngMô tả
git restore <file>--stagedBỏ thay đổi chưa staged trong working directory; thêm --staged để unstage một file.
git reset <commit>--soft--mixed--hardĐưa HEAD về một commit khác. --hard xoá luôn thay đổi trong working directory.
git revert <commit>-nTạo commit mới đảo ngược tác dụng của một commit cũ — an toàn cho lịch sử đã push và dùng chung.
git stashpoplist-uCất tạm thay đổi chưa commit để chuyển việc khác, lấy lại sau bằng stash pop.
Lưu ý: git reset --hard xoá vĩnh viễn thay đổi chưa commit trong working directory — không có staging area hay commit nào để cứu lại. Chạy git status và git diff trước để chắc chắn không mất gì cần giữ.

Lệnh nâng cao

LệnhTuỳ chọn thường dùngMô tả
git cherry-pick <commit>-n--abort--continueÁp dụng riêng một commit từ nhánh khác vào nhánh hiện tại, không cần merge cả nhánh.
git rebase -i HEAD~npick / squash / fixup / dropInteractive rebase: sửa message, gộp, hoặc xoá bớt n commit gần nhất trước khi push.
git bisect startgoodbadresetBinary search qua lịch sử commit để tìm chính xác commit gây ra lỗi.
git reflog–Lịch sử di chuyển của HEAD — cứu lại commit tưởng đã "mất" sau một reset --hard nhầm.
git tag <name>-a -m-dĐánh dấu một điểm cụ thể trong lịch sử, thường dùng cho version/release firmware.
git submodule add <url>update --init --recursiveQuản lý repo con bên trong repo chính — hay gặp khi kéo SDK/HAL của hãng chip làm dependency.

Đọc hiểu conflict marker trước khi bắt đầu

Cả bốn lệnh bên dưới đều có thể dẫn tới cùng một thứ: Git chèn thẳng marker vào file khi không tự gộp được. Hiểu rõ cấu trúc này thì phần còn lại chỉ là lặp lại quy trình.

Phần "ours" — nhánh bạn đang đứng (HEAD)
Phần "theirs" — nhánh/commit đang được đưa vào
Dòng marker do Git chèn vào
drivers/uart.c
<<<<<<< HEADvoid uart_init(uint32_t baudrate) { USART1->BRR = SystemCoreClock / baudrate; }=======void uart_init(uint32_t baudrate, uint8_t parity) { USART1->BRR = SystemCoreClock / baudrate; USART1->CR1 |= (parity << 9); }>>>>>>> feature/uart-driver

Việc cần làm luôn giống nhau: sửa lại nội dung thành đúng cái bạn muốn (giữ một bên, gộp cả hai, hoặc viết lại hoàn toàn), xoá cả ba dòng marker (<<<<<<<, =======, >>>>>>>), rồi báo cho Git biết bằng git add.

Conflict khi git merge

Xảy ra khi nhánh hiện tại và nhánh được merge vào cùng sửa một vùng code mà Git không tự quyết được nên giữ bên nào.

  1. Chạy merge và gặp conflict

    $ git switch main
$ git merge feature/uart-driver
Auto-merging drivers/uart.c
CONFLICT (content): Merge conflict in drivers/uart.c
Automatic merge failed; fix conflicts and then commit the result.

  2. Kiểm tra file nào đang conflict

    git status luôn liệt kê rõ file nào cần xử lý:

    $ git status
On branch main
You have unmerged paths.
  (fix conflicts and run "git commit")
  (use "git merge --abort" to abort the merge)

Unmerged paths:
  (use "git add <file>..." to mark resolution)
        both modified:   drivers/uart.c

  3. Mở file, sửa nội dung conflict

    Xem lại khối marker ở mục trên, chọn giữ bản nào (hoặc gộp cả hai), rồi xoá ba dòng marker.

  4. Đánh dấu đã resolve và commit

    $ git add drivers/uart.c
$ git commit

    Git tự mở editor với message mặc định kiểu Merge branch 'feature/uart-driver' — giữ nguyên hoặc chỉnh lại tuỳ ý. Muốn huỷ merge, quay về trạng thái trước đó: git merge --abort.

Conflict khi git rebase

Khác với merge, rebase phát lại (replay) từng commit một lên nhánh đích — nên conflict có thể xảy ra nhiều lần, mỗi lần ứng với một commit, thay vì chỉ một lần duy nhất.

  1. Rebase và dừng lại ở commit gây conflict

    $ git switch feature/lvgl-ui
$ git rebase main
Auto-merging src/ui/screen_main.c
CONFLICT (content): Merge conflict in src/ui/screen_main.c
error: could not apply a1b2c3d... Add temperature widget to main screen
Resolve all conflicts manually, mark them as resolved with
"git add/rm <conflicted_files>", then run "git rebase --continue".

  2. Sửa conflict như bình thường, rồi tiếp tục rebase

    $ git add src/ui/screen_main.c
$ git rebase --continue

    Nếu commit tiếp theo cũng conflict, quy trình lặp lại y hệt cho tới khi hết commit cần replay.

  3. Các lối thoát khi cần

    git rebase --skip bỏ qua hẳn commit hiện tại (dùng khi thay đổi của nó đã có ở nơi khác rồi). git rebase --abort huỷ toàn bộ, quay về đúng trạng thái trước khi rebase.

Lưu ý: rebase viết lại hash của commit. Tránh rebase một nhánh đã push và đang có người khác cùng dùng, trừ khi cả team đã thống nhất — và khi push lại, ưu tiên --force-with-lease thay vì --force.

Conflict khi git cherry-pick

Xảy ra khi commit muốn lấy sang nhánh khác đụng vào phần code đã thay đổi khác đi ở nhánh đích.

  1. Cherry-pick và gặp conflict

    $ git switch release/v1.2
$ git cherry-pick 9f8e7d6
Auto-merging Kconfig
CONFLICT (content): Merge conflict in Kconfig
error: could not apply 9f8e7d6... Fix I2C timeout default value
hint: after resolving the conflicts, mark the corrected paths
hint: with 'git add <paths>' or 'git rm <paths>'
hint: and commit the result with 'git commit'

  2. Sửa file, thêm vào staging, rồi tiếp tục

    $ git add Kconfig
$ git cherry-pick --continue

  3. Khi pick nhiều commit cùng lúc

    Với git cherry-pick A B C, hễ commit nào conflict thì xử lý y hệt bước trên rồi --continue để Git pick tiếp các commit sau. --skip bỏ qua riêng commit đang gây conflict, --abort huỷ toàn bộ thao tác.

Conflict khi git pull

git pull về bản chất là git fetch nối theo git merge (mặc định) hoặc git rebase (nếu bật --rebase) — nên conflict xảy ra sẽ rơi đúng vào một trong hai tình huống đã nói ở trên, chỉ khác là diễn ra "ẩn" bên trong một lệnh duy nhất.

  1. Trường hợp mặc định (fetch + merge)

    $ git pull origin main
remote: Enumerating objects: 12, done.
Auto-merging CMakeLists.txt
CONFLICT (content): Merge conflict in CMakeLists.txt
Automatic merge failed; fix conflicts and then commit the result.

    Xử lý y hệt phần conflict khi merge ở trên: sửa file, git add, git commit — hoặc git merge --abort để huỷ.

  2. Trường hợp dùng --rebase (fetch + rebase)

    $ git pull --rebase origin main
Auto-merging CMakeLists.txt
CONFLICT (content): Merge conflict in CMakeLists.txt
error: could not apply 5c6d7e8... Update toolchain version

    Xử lý y hệt phần conflict khi rebase: sửa file, git add, git rebase --continue — hoặc git rebase --abort.

  3. Chọn hẳn một quy ước cho cả team

    Lẫn lộn giữa hai kiểu pull trong cùng một repo dễ gây khó hiểu khi review lịch sử. Chọn một, đặt cấu hình cố định:

    $ git config --global pull.rebase true    # luôn rebase khi pull
$ git config --global pull.rebase false   # luôn merge khi pull (mặc định)
$ git config --global pull.ff only        # chỉ pull khi fast-forward được
