V4L2 & Kiến Trúc Camera Stack trên Raspberry Pi 5

Cách kernel Linux nhìn thấy camera, vì sao camera CSI trên RPi5 phức tạp hơn webcam USB, và cách đọc pipeline phần cứng thông qua Media Controller trước khi chạm vào bất kỳ công cụ capture nào.

Sensor: OV5647 (OmniVision, 5MP)
CSI receiver: rp1-cfe
ISP: pispbe (PiSP Back End)
I2C addr: 0x36 (bus 10)

01V4L2 là gì

V4L2 (Video4Linux2) là kernel subsystem quản lý toàn bộ thiết bị video trên Linux — camera, TV tuner, HW codec, video output.

Nó expose ra userspace dưới dạng device node (/dev/video*, /dev/media*, /dev/v4l-subdev*) cùng một bộ ioctl chuẩn hoá (VIDIOC_*). Với camera đơn giản như webcam USB (UVC), driver USB tự làm hết việc negotiate giữa sensor và ISP nội bộ, nên một device node /dev/video0 là đủ dùng.

Camera CSI (MIPI) như OV5647 thì khác: sensor, bộ nhận CSI-2, và ISP là 3 khối phần cứng tách biệt, kết nối với nhau qua một pipeline có thể cấu hình được. Để mô tả và điều khiển pipeline này, V4L2 có thêm hai API mở rộng:

APIVai tròDevice node
V4L2 coreCapture buffer, format, streaming trên node cuối cùng/dev/videoN
V4L2 subdevĐiều khiển từng khối phần cứng riêng lẻ (sensor, CSI bridge, ISP front-end)/dev/v4l-subdevN
Media Controller (MC)Mô tả graph kết nối giữa các subdev — entity, pad, link/dev/mediaN
💡 Ý chính

Webcam USB = 1 hộp đen, 1 device node. Camera CSI = nhiều IC rời cần Media Controller để "nối dây" bằng phần mềm trước khi capture được. Đây là gốc rễ của mọi phức tạp sẽ gặp trong Phần 2 và 3.

02Kiến trúc Camera Stack trên RPi5

RPi5 dùng chip RP1 (I/O controller phụ trợ, tách biệt khỏi SoC BCM2712 chính) để xử lý CSI-2. Đường đi từ ánh sáng đến file JPEG đi qua 4 lớp:

┌──────────────────────────────────────────────────────┐
│              Ứng dụng (rpicam-still, app...)          │
└───────────────────────┬────────────────────────────────┘
                         │ libcamera API
┌───────────────────────▼────────────────────────────────┐
│                    libcamera (userspace)               │
│         quản lý pipeline, IPA (3A: AE/AWB/AF), tuning   │
└──────┬──────────────────────────────────┬──────────────┘
       │ V4L2 subdev + Media Controller    │ IPA (thuật toán)
┌──────▼──────────┐                ┌───────▼──────────────┐
│   rp1-cfe          │                │   pisp IPA module      │
│  (CSI-2 receiver) │                │   (ov5647.json tuning) │
│  driver kernel     │                └────────────────────────┘
└──────┬──────────┘
       │ nội bộ (memory / FE hardware path)
┌──────▼──────────┐
│   pispbe          │   ISP phần cứng: debayer, denoise, AWB apply
│  (PiSP Back End)  │   RAW Bayer → YUV/RGB/JPEG
└──────┬──────────┘
       │ MIPI CSI-2 (ngược dòng lên trên)
┌──────▲──────────┐
│   OV5647          │  Sensor vật lý — I2C 10-0036 (điều khiển) + CSI-2 (dữ liệu)
└──────────────────┘
Thành phầnLoạiVai trò
OV5647Phần cứngSensor — thu ánh sáng, xuất RAW Bayer 10-bit qua MIPI CSI-2, nhận lệnh điều khiển (exposure, gain...) qua I2C
rp1-cfeKernel driverCamera Front End — nhận luồng CSI-2, expose ra dạng V4L2 (video node + subdev)
pispbeKernel driver + HWPiSP Back End — ISP phần cứng: debayer, denoise, AWB, xuất YUV/RGB
libcameraUserspace libraryQuản lý toàn bộ pipeline, chạy thuật toán 3A, negotiate format — đây là lớp xử lý toàn bộ độ phức tạp mà Phần 2 sẽ bàn tới khi bỏ qua nó
rpicam-appsCLI toolrpicam-hello/-still/-vid — chỉ có trên RPi, gọi libcamera trực tiếp
⚠️ Khác biệt quan trọng so với RPi4 trở về trước

RPi 1-4 dùng driver bcm2835-unicam — đơn giản, mỗi CSI link chỉ có 1 stream. RPi5 dùng rp1-cfe hỗ trợ multiplexed streams (nhiều stream ảo trên 1 link CSI vật lý, dùng cho ống kính đa camera, embedded metadata...). Tính năng này là nguyên nhân trực tiếp gây lỗi VIDIOC_STREAMON: Invalid argument khi thử capture V4L2 thuần trên RPi5 — sẽ mổ xẻ kỹ ở Phần 2.

03Nhận diện camera — 3 cách

Ba cách độc lập để xác nhận kernel đã "thấy" camera, dùng bổ sung cho nhau khi debug.

3A. Device file trong /dev

bash
ls /dev/video* 2>/dev/null && echo "--- Camera devices found ---" || echo "No video devices found"

Trên RPi5 sẽ thấy rất nhiều node — /dev/video0 đến /dev/video35 là bình thường. Phần lớn là virtual subdevice của ISP (pispbe), không phải camera vật lý. So sánh: laptop/PC với webcam USB thường chỉ có /dev/video0 và /dev/video1 (1 capture + 1 metadata).

3B. v4l2-ctl --list-devices

bash
v4l2-ctl --list-devices
output
pispbe (platform:1000880000.pisp_be):
        /dev/video20 đến /dev/video35
        /dev/media2, /dev/media3

rp1-cfe (platform:1f00110000.csi):
        /dev/video0 đến /dev/video7
        /dev/media0

rpi-hevc-dec (platform:rpi-hevc-dec):
        /dev/video19
        /dev/media1
DriverÝ nghĩa
rp1-cfeCamera Front End — nhận dữ liệu RAW từ sensor qua CSI-2 → camera thật nằm phía sau driver này
pispbePiSP Back End — ISP xử lý ảnh (debayer, denoise)
rpi-hevc-decBộ giải mã video HEVC (H.265) — không liên quan camera, có thể bỏ qua

3C. Kernel log (dmesg)

bash
dmesg | grep -iE "(csi|ov5|imx|ar[0-9]{4}|sensor|camera)" \
       | grep -v "ieee80211\|brcm\|SCSI" \
       | tail -20

Bộ lọc imx|ov|ar[0-9]{4} bắt tên các sensor phổ biến: imx = Sony, ov = OmniVision, ar = onsemi/ams. Dòng loại trừ ieee80211|brcm|SCSI giúp bớt nhiễu từ log WiFi/storage trên RPi.

Dòng log hay gặp — không phải lỗi

rp1-cfe ...csi: csi2_ch0 node link is not enabled. — đây là log trạng thái khởi tạo, xuất hiện khi link chưa từng được bật (chưa có app nào capture). Không cần xử lý gì; libcamera/rpicam sẽ tự enable link khi bắt đầu chụp.

Cách nhanh: đếm sensor thật qua /sys/class/video4linux

3 cách trên cho biết camera "có tồn tại", nhưng để biết chính xác subdev nào là sensor thật (khác với các bridge/ISP nội bộ tên csi2, pisp-fe, rp1-*):

bash
for dev in /sys/class/video4linux/v4l-subdev*; do
    name=$(cat "$dev/name" 2>/dev/null)
    if echo "$name" | grep -qvE "^csi|^pisp|^rp1|^isp"; then
        echo "[SENSOR] $name -> /dev/$(basename $dev)"
    else
        echo "[HW]     $name -> /dev/$(basename $dev)"
    fi
done
output
[HW]     csi2      -> /dev/v4l-subdev0    # CSI-2 bridge
[HW]     pisp-fe   -> /dev/v4l-subdev1    # ISP front end
[SENSOR] ov5647 10-0036 -> /dev/v4l-subdev2   # ← CAMERA THẬT

10-0036 = quy ước đặt tên chuẩn cho subdevice gắn qua I2C: bus 10, địa chỉ 0x36 — đây chính là địa chỉ I2C cố định của OV5647.

04Đọc pipeline qua Media Controller

media-ctl là công cụ duy nhất cho bạn thấy toàn bộ graph kết nối phần cứng — thứ mà v4l2-ctl --list-devices không thể hiện.

bash
ls /dev/media*
media-ctl -d /dev/media0 -p
output
Media device information
    driver   rp1-cfe
    model    rp1-cfe

- entity 16: ov5647 10-0036
    -> "csi2":0 [ENABLED,IMMUTABLE]

- entity 1: csi2 (8 pads, 8 links)
    <- "ov5647 10-0036":0 [ENABLED,IMMUTABLE]
    -> "rp1-cfe-csi2_ch0":0 []           # disabled — bypass ISP (raw)
    -> "pisp-fe":0 [ENABLED]             # enabled — qua ISP (mặc định)

- entity 18: rp1-cfe-csi2_ch0 (/dev/video0)   # Raw Bayer output
    <- "csi2":4 []

- entity 34: rp1-cfe-fe_image0 (/dev/video4)  # Processed output (qua ISP)
    <- "pisp-fe":2 [ENABLED]

3 khái niệm cần nắm để đọc output này:

Khái niệmÝ nghĩa
EntityMột khối chức năng — sensor, bridge, hoặc 1 video device node
PadĐiểm kết nối vào/ra của entity (SINK = nhận, SOURCE = xuất)
LinkDây nối giữa 2 pad — có thể ENABLED hoặc disabled, IMMUTABLE nghĩa là không thể đổi (link vật lý cố định)
Đọc nhanh sơ đồ trên

Mặc định, dữ liệu chảy: ov5647 → csi2 → pisp-fe (ISP) → /dev/video4. Đường csi2 → rp1-cfe-csi2_ch0 (/dev/video0) là đường "tắt qua ISP" để lấy RAW Bayer thô, mặc định đang disabled. Muốn RAW thì phải tự bật link này bằng media-ctl -l — chi tiết và các lỗi thường gặp khi làm việc này nằm ở Phần 2.

05Truy vấn thông tin sensor chi tiết

Sau khi biết subdev nào là sensor thật (/dev/v4l-subdev2 trong ví dụ này), có thể hỏi trực tiếp format, resolution, và toàn bộ control mà sensor hỗ trợ.

Format hiện tại (mediabus format)

bash
v4l2-ctl --device=/dev/v4l-subdev2 --get-subdev-fmt
output
ioctl: VIDIOC_SUBDEV_G_FMT (pad=0,stream=0)
    Width/Height  : 1920/1080
    Mediabus Code : 0x300e (MEDIA_BUS_FMT_SGBRG10_1X10)   ← Bayer 10-bit GBRG
    Field         : None
    Colorspace    : Raw

Tất cả resolution sensor hỗ trợ

bash
# code=0x300e là SGBRG10_1X10 (Bayer 10-bit gốc của OV5647)
v4l2-ctl --device=/dev/v4l-subdev2 \
         --list-subdev-framesizes=pad=0,code=0x300e
output
Size Range: 2592x1944 - 2592x1944   ← Full resolution (5MP)
Size Range: 1920x1080 - 1920x1080   ← 1080p (crop mode)
Size Range: 1296x972  - 1296x972    ← ~1.3MP, mode gần HD nhất (binned)
Size Range: 640x480   - 640x480     ← VGA
Không có 1280×720 native

OV5647 không có sensor mode 1280×720 gốc. 1920x1080 tồn tại nhưng là crop mode (cắt từ vùng cảm biến lớn hơn, không phải scale), còn mode gần "HD" nhất theo tỉ lệ đầy đủ khung hình là 1296x972 (binned mode — gộp pixel để tăng độ nhạy sáng và giảm noise).

Controls điều chỉnh được

bash
v4l2-ctl --device=/dev/v4l-subdev2 --list-ctrls
NhómControlGhi chú
Userexposureint, min=4 max=1100 step=1 default=1000
Usergain_automaticbool, default=0
Userhorizontal_flip / vertical_flipbool
Cameraauto_exposuremenu — 0 = Auto, 1 = Manual (ngược trực giác!)
Image Sourceanalogue_gainint, min=16 max=1023 default=32
Image Processingpixel_rate, link_frequencyread-only, thông tin timing
bash
# Set exposure thủ công
v4l2-ctl --device=/dev/v4l-subdev2 --set-ctrl=auto_exposure=1  # 1 = Manual
v4l2-ctl --device=/dev/v4l-subdev2 --set-ctrl=exposure=500

# Đọc lại nhiều control cùng lúc
v4l2-ctl --device=/dev/v4l-subdev2 \
  --get-ctrl=auto_exposure,gain_automatic,exposure,analogue_gain

06Bayer Pattern & vai trò của ISP

Sensor màu không đo đủ 3 kênh RGB tại mỗi pixel — nó dùng lưới lọc màu (Color Filter Array), mỗi pixel chỉ thu một màu:

G B G B G B
R G R G R G
G B G B G B
R G R G R G

SGBRG10 (format của OV5647) nghĩa là: hàng đầu bắt đầu bằng G-B, hàng kế bắt đầu bằng R-G, mỗi giá trị 10-bit. ISP (pispbe) thực hiện bước debayer (hay demosaic) — nội suy để tính đủ 3 kênh RGB cho từng pixel, đồng thời chạy các thuật toán denoise và White Balance.

Vì sao điều này quan trọng cho xử lý ảnh/AI

Nếu lấy RAW Bayer trực tiếp từ /dev/video0 (bỏ qua ISP), bạn nhận dữ liệu chưa debayer — không thể đưa thẳng vào OpenCV như ảnh RGB thường mà phải tự debayer bằng cv2.cvtColor(..., cv2.COLOR_BayerGB2BGR) hoặc tương đương. Với hầu hết tác vụ AI/CV, lấy ảnh đã qua ISP (YUV/RGB) từ pispbe — như picamera2 làm mặc định — đơn giản và ít lỗi hơn nhiều.

07Xác nhận nhanh: rpicam-hello

Sau khi đã hiểu kiến trúc, cách nhanh nhất để xác nhận toàn bộ chuỗi (sensor → CSI → ISP → libcamera) hoạt động đúng là dùng bộ công cụ chính thức của Raspberry Pi.

Đổi tên tool trên Bookworm trở lên

Raspberry Pi OS Bookworm+ đã đổi tên: libcamera-hello → rpicam-hello (tương tự -still, -vid). Bản cũ vẫn còn dạng symlink ở một số bản dựng nhưng không nên phụ thuộc vào đó.

bash
rpicam-hello --list-cameras
output
Available cameras
-----------------
0 : ov5647 [2592x1944 10-bit GBRG] (/base/axi/pcie@1000120000/rp1/i2c@88000/ov5647@36)
    Modes: 'SGBRG10_CSI2P' : 640x480 [62.50 fps - (16, 0)/2560x1920 crop]
                             1296x972 [46.34 fps - (0, 0)/2592x1944 crop]
                             1920x1080 [32.81 fps - (348, 434)/1928x1080 crop]
                             2592x1944 [15.63 fps - (0, 0)/2592x1944 crop]
bash
rpicam-still -o photo_$(date +%Y%m%d_%H%M%S).jpg \
             --width 1920 --height 1080 \
             -t 3000

-t 3000: 3 giây preview trước khi chụp để auto-exposure/AWB ổn định. Nếu thấy cảnh báo Consider using the --zsl option — đây chỉ là gợi ý tối ưu (Zero Shutter Lag, dùng temporal denoise), không phải lỗi; thêm --zsl vào lệnh cho chất lượng tốt hơn.

Checklist debug khi camera không được nhận

bash
# 1. Camera có được nhận không
rpicam-hello --list-cameras

# 2. Kernel log có lỗi không
dmesg | grep -i "error\|fail\|camera\|ov5647"

# 3. Bus I2C (camera giao tiếp qua I2C) — thử vài bus nếu không chắc số
i2cdetect -y 10

# 4. Quyền truy cập device
ls -la /dev/video0
groups $USER

# 5. Thêm user vào group video nếu thiếu quyền
sudo usermod -aG video $USER

09Lệnh tham khảo nhanh

bash
# Liệt kê tất cả camera device
v4l2-ctl --list-devices

# Xem chi tiết một device
v4l2-ctl --device=/dev/video0 --all

# Đọc toàn bộ pipeline Media Controller
media-ctl -d /dev/media0 -p

# Tìm subdev là sensor thật (không phải csi2/pisp/rp1)
for dev in /sys/class/video4linux/v4l-subdev*; do
    grep -qvE "^csi|^pisp|^rp1|^isp" "$dev/name" 2>/dev/null && \
    echo "$(cat $dev/name) -> /dev/$(basename $dev)"
done

# Format & resolution của sensor
v4l2-ctl --device=/dev/v4l-subdev2 --get-subdev-fmt
v4l2-ctl --device=/dev/v4l-subdev2 --list-subdev-framesizes=pad=0,code=0x300e
v4l2-ctl --device=/dev/v4l-subdev2 --list-ctrls

# Kernel log liên quan camera
dmesg | grep -i "camera\|csi\|ov5647"

# Xác nhận nhanh bằng rpicam
rpicam-hello --list-cameras
rpicam-still --zsl -o anh.jpg
