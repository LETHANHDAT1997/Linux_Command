GStreamer cho Camera CSI trên RPi5

Pipeline text đơn giản, cross-platform thật sự, và framework duy nhất trong bộ 4 hỗ trợ pipeline động lẫn streaming mạng native. Phần cuối mở rộng sang appsink để đưa frame vào Python cho xử lý AI.

GStreamer: 1.26.2
Plugin CSI: gstreamer1.0-libcamera 0.7.1+rpt20260609

01GStreamer là gì

Multimedia pipeline framework: dữ liệu chảy qua chuỗi element nối bằng !.

[source] ! [filter/transform] ! [sink]

GStreamer là lớp trên — nó vẫn cần backend bên dưới để thật sự nói chuyện với phần cứng:

gst-launch-1.0 (pipeline text)
       │
       ▼
GStreamer Framework
       │
       ├── v4l2src plugin      → V4L2 kernel API  → Camera USB / CSI (board cũ)
       ├── libcamerasrc plugin → libcamera        → Camera CSI (RPi5, hiện đại)
       └── pipewiresrc plugin  → PipeWire          → Camera qua audio/video server

Đây là lý do GStreamer giải quyết được vấn đề routing của RPi5 đã gặp ở Phần 2: khi dùng libcamerasrc, chính libcamera lo cấu hình Media Controller — GStreamer chỉ cần biết caps mong muốn.

04Cấu hình thông số qua caps

Với GStreamer, thông số nằm trong caps (capabilities) — filter giữa 2 element: element ! caps-filter ! element

caps syntax
video/x-raw,format=NV12,width=1296,height=972,framerate=46/1
TrườngÝ nghĩaVí dụ
formatPixel format — phải chỉ định rõNV12, YUY2, I420
width/heightKích thước pixel1296, 972
framerateFPS dạng fraction46/1, 30/1
⚠️ Bắt buộc: format=NV12 với libcamerasrc

Nếu chỉ viết video/x-raw,width=...,height=... mà không có format, libcamerasrc sẽ tự negotiate sang video/x-bayer (RAW Bayer chưa debayer) → pipeline lỗi not-negotiated (-4) ngay khi gặp videoconvert (element này không hiểu RAW Bayer).

bash
# ĐÚNG — có format=NV12
gst-launch-1.0 libcamerasrc ! "video/x-raw,format=NV12,width=1296,height=972" ! fakesink

# SAI — thiếu format → not-negotiated
# gst-launch-1.0 libcamerasrc ! "video/x-raw,width=1296,height=972" ! fakesink

# USB camera (v4l2src)
gst-launch-1.0 v4l2src device=/dev/video0 \
  ! "video/x-raw,format=YUY2,width=1280,height=720,framerate=30/1" ! fakesink

Set control camera (exposure, gain)

bash
# Với libcamerasrc: dùng v4l2-ctl trên subdev trước khi chạy pipeline
v4l2-ctl --device=/dev/v4l-subdev2 --set-ctrl=auto_exposure=0
v4l2-ctl --device=/dev/v4l-subdev2 --set-ctrl=gain_automatic=1

# Với v4l2src: property extra-controls
gst-launch-1.0 v4l2src device=/dev/video0 extra-controls="c,exposure=500" \
  ! "video/x-raw,format=YUY2" ! fakesink

06Preview live & vấn đề Wayland

RPi5 dùng display server Wayland. autovideosink mặc định thường chọn xvimagesink (X11) — chạy qua Xwayland gây lỗi đồng bộ frame, biểu hiện là chớp tắt (alternating black frames).

SinkĐặc điểm
waylandsinkNative cho Wayland, vẽ trực tiếp lên compositor. Chỉ chạy được trên Wayland.
glimagesink khuyên dùngDùng lớp trừu tượng OpenGL (EGL) — tự động kết nối Wayland compositor không qua Xwayland. Zero-copy: upload buffer camera (dma-buf) thẳng lên GPU texture, giải phóng CPU. Portable: chạy được cả X11/Wayland/Windows/macOS — mang nguyên pipeline sang máy khác không cần sửa.
bash
# Preview OpenGL — mượt, không chớp tắt, chạy cả Wayland & X11
gst-launch-1.0 libcamerasrc ! video/x-raw,format=NV12,width=1296,height=972 \
  ! queue ! videoconvert ! queue ! glimagesink

# Preview Wayland native — chỉ chạy trên hệ thống Wayland
gst-launch-1.0 libcamerasrc ! video/x-raw,format=NV12,width=1296,height=972 \
  ! queue ! videoconvert ! queue ! waylandsink

07So sánh: libcamerasrc vs v4l2src

Tiêu chílibcamerasrcv4l2src
BackendlibcameraV4L2 kernel API trực tiếp
CSI camera RPi5✅ Hoạt động❌ Routing issue
CSI camera RPi4/cũ✅ Hoạt động✅ Hoạt động
USB camera⚠️ Chạy được nhưng thừa✅ Hoạt động tốt, đúng mục đích
Nền tảng non-RPi có ISP riêng✅ Nếu có pipeline handler (IPU3, rkisp1...)❌ Phải tự cấu hình Media Controller thủ công
Auto-exposure/WB✅ Tự động (IPA 3A)⚠️ Phải set thủ công
Cài đặtgstreamer1.0-libcameragstreamer1.0-plugins-good
🔧 libcamera phổ quát tới đâu? Bổ sung sau câu hỏi

"libcamerasrc chủ yếu cho RPi" (câu gốc ở bản trước) là cách nói rút gọn quá tay. libcamera có pipeline handler thật cho nhiều nền tảng khác: Intel IPU3/IPU6 (một số laptop Kaby Lake/Apollo Lake trở lên), RockChip RK3399 (rkisp1 — nhiều board SBC dùng chip này), NXP i.MX8MP, TI J721e, Arm Mali C55, một phần Qualcomm Snapdragon — cộng UVC webcam thông thường qua pipeline handler uvcvideo. Vài nền tảng khác (Allwinner A31, i.MX7, MediaTek Genio 300) mới chỉ hỗ trợ raw capture, chưa đầy đủ ISP.

Nên tách 2 nghĩa của "phổ quát": cài đặt được — đúng, package GStreamer/libcamera không khoá cứng vào RPi, apt cài trên mọi Linux. Cần thiết/có ích — chỉ khi camera không phải UVC thường, vì UVC đã chạy tốt sẵn qua v4l2src, dùng libcamerasrc cho nó là thừa việc. Và trong toàn bộ danh sách trên, pipeline handler của RPi vẫn là bản trưởng thành/được đầu tư nhiều nhất — vì chính kỹ sư Raspberry Pi Ltd trực tiếp maintain phần đó của dự án libcamera; các nền tảng khác độ hoàn thiện không đồng đều.

08🆕 Mới appsink — đưa frame vào Python/OpenCV

Mọi ví dụ ở trên dừng ở "lưu file" hoặc "hiển thị màn hình". Để xử lý ảnh/AI thật sự, cần lấy từng frame ra dưới dạng mảng số trong code — đây là việc của appsink.

Khi nào dùng appsink thay vì picamera2 (Phần 4)?

Dùng appsink khi pipeline cần các khối GStreamer khác không có trong picamera2 — ví dụ tee ra vừa AI vừa RTSP stream cùng lúc, hoặc hardware encode phức tạp. Nếu chỉ cần "camera → numpy array → OpenCV" đơn giản, picamera2 ở Phần 4 gọn hơn và không cần học GObject Introspection.

bash — cài đặt
sudo apt install python3-gi gir1.2-gst-plugins-base-1.0
python3 -c "import gi; gi.require_version('Gst','1.0'); print('OK')"
python — appsink_opencv.py
import gi
gi.require_version('Gst', '1.0')
from gi.repository import Gst, GLib
import numpy as np
import cv2

Gst.init(None)

WIDTH, HEIGHT = 640, 480

# BGR: format OpenCV muốn ngay từ videoconvert, khỏi phải tự đổi kênh màu
pipeline_str = (
    f"libcamerasrc ! video/x-raw,format=NV12,width={WIDTH},height={HEIGHT} "
    f"! videoconvert ! video/x-raw,format=BGR "
    f"! appsink name=sink emit-signals=true max-buffers=1 drop=true"
)
pipeline = Gst.parse_launch(pipeline_str)
appsink = pipeline.get_by_name("sink")

def on_new_sample(sink):
    sample = sink.emit("pull-sample")
    buf = sample.get_buffer()
    ok, mapinfo = buf.map(Gst.MapFlags.READ)
    if not ok:
        return Gst.FlowReturn.ERROR

    frame = np.ndarray((HEIGHT, WIDTH, 3), buffer=mapinfo.data, dtype=np.uint8)

    # ---- xử lý ảnh / gọi model AI tại đây ----
    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
    edges = cv2.Canny(gray, 80, 160)
    cv2.imshow("edges", edges)
    cv2.waitKey(1)
    # -------------------------------------------

    buf.unmap(mapinfo)
    return Gst.FlowReturn.OK

appsink.connect("new-sample", on_new_sample)
pipeline.set_state(Gst.State.PLAYING)

loop = GLib.MainLoop()
try:
    loop.run()
except KeyboardInterrupt:
    pass
finally:
    pipeline.set_state(Gst.State.NULL)
Tham số appsinkVì sao quan trọng cho AI/CV
emit-signals=trueBật callback new-sample — bắt buộc để đọc frame trong Python thay vì chỉ pull thủ công
max-buffers=1 drop=trueLuôn giữ frame mới nhất, tự động drop frame cũ nếu code xử lý chậm hơn camera — tránh loop bị dồn ứ (backlog) làm tăng latency dần theo thời gian
format=BGR trên caps sau videoconvertKhớp thẳng thứ tự kênh màu OpenCV dùng — khỏi phải cv2.cvtColor(..., COLOR_RGB2BGR) mỗi frame

09🆕 Mới Streaming qua mạng cho AI từ xa

Khác với chụp ảnh tĩnh — nếu model AI chạy trên máy khác (server mạnh hơn, hoặc muốn tách camera node khỏi compute node), cần đẩy stream qua mạng thay vì xử lý tại chỗ.

UDP/RTP — đơn giản, độ trễ thấp, không cần server

bash — bên gửi (RPi5)
gst-launch-1.0 libcamerasrc ! video/x-raw,format=NV12,width=1296,height=972 \
  ! videoconvert ! x264enc tune=zerolatency bitrate=2000 speed-preset=ultrafast \
  ! rtph264pay ! udpsink host=192.168.1.100 port=5000
bash — bên nhận (server chạy model AI)
gst-launch-1.0 udpsrc port=5000 \
  ! "application/x-rtp,encoding-name=H264,payload=96" \
  ! rtph264depay ! avdec_h264 ! videoconvert \
  ! appsink emit-signals=true max-buffers=1 drop=true

tune=zerolatency + speed-preset=ultrafast: đánh đổi chất lượng nén lấy độ trễ thấp — đúng hướng cho pipeline AI thời gian thực hơn là streaming xem giải trí.

RTSP thật sự — nhiều client cùng xem, có thể reconnect

UDP điểm-điểm phù hợp 1 gửi–1 nhận đã biết trước IP. Muốn có URL RTSP chuẩn (rtsp://ip:8554/stream) để nhiều client kết nối/ngắt tuỳ ý, cần một RTSP server thật — GStreamer tự thân không phải là server, phải dùng thêm thư viện gst-rtsp-server (viết vài chục dòng Python/C) hoặc một binary có sẵn như MediaMTX nhận input RTP từ lệnh udpsink ở trên và tự phục vụ RTSP.

Khi nào cần RTSP thay vì UDP thẳng

Nếu chỉ có 1 model AI cố định đọc stream, UDP/RTP thẳng đơn giản và đủ dùng. Nếu cần nhiều tiến trình cùng xem stream (ví dụ vừa ghi log vừa chạy inference vừa xem trực tiếp để debug), RTSP server đáng đầu tư hơn.
