04Camera USB — trường hợp đơn giản nhất

Webcam USB (UVC) tự expose /dev/video0 hoàn chỉnh, không cần cấu hình Media Controller. Cả 3 công cụ đều dùng trực tiếp được, ngay lập tức:

bash — ffmpeg
ffmpeg -f v4l2 -video_size 1280x720 -i /dev/video0 -frames:v 1 photo.jpg -y
bash — v4l2-ctl
v4l2-ctl --device=/dev/video0 \
  --set-fmt-video=width=1280,height=720,pixelformat=YUYV \
  --stream-mmap --stream-to=photo.raw --stream-count=1

# Convert raw YUYV sang JPEG
ffmpeg -f rawvideo -pixel_format yuyv422 -video_size 1280x720 \
       -i photo.raw photo.jpg
bash — gstreamer
gst-launch-1.0 v4l2src device=/dev/video0 num-buffers=1 \
  ! "video/x-raw,format=YUY2,width=1280,height=720" \
  ! videoconvert ! jpegenc ! filesink location=photo.jpg

Không có gì đặc biệt ở đây — đây chính xác là trải nghiệm "V4L2 hoạt động như quảng cáo". Vấn đề chỉ bắt đầu khi sang camera CSI trên RPi5.

05Camera CSI trên RPi5 — vì sao phức tạp hơn hẳn

Camera USB: sensor + ISP nằm trong 1 thiết bị, driver expose ra /dev/video0 đơn giản. Camera CSI trên RPi5: sensor, CSI receiver, ISP là 3 phần cứng tách biệt, nối qua Media Controller pipeline (xem chi tiết kiến trúc ở Phần 1).

⚠️ Gốc rễ kỹ thuật: multiplexed streams

RPi5 dùng driver rp1-cfe hỗ trợ nhiều stream ảo trên 1 link CSI vật lý (multiplexed streams) — một tính năng RPi4 trở về trước không có. Muốn dùng đúng, mỗi output node phải được cấu hình qua một routing table (ioctl VIDIOC_SUBDEV_S_ROUTING) trước khi stream. libcamera tự làm việc này; tool V4L2 thuần thì không.

Thế hệDriver CSIMultiplexed streams
RPi 1–4bcm2835-unicamKhông
RPi 5rp1-cfeCó — cần routing table
Jetson / i.MX8tegra-vi / imx-mipi-csisKhông

06Nhật ký lỗi thực tế ✅ Đã kiểm chứng

Ba lỗi gặp phải khi thử capture RAW trực tiếp từ /dev/video0 bằng V4L2/ffmpeg thuần, bỏ qua libcamera:

❌ Lỗi 1 — VIDIOC_STREAMON: Invalid argument

output
VIDIOC_STREAMON returned -1 (Invalid argument)
Buffer size sau REQBUFS: length=0, offset=0x0

Nguyên nhân: chưa cấu hình routing table cho subdevice csi2. v4l2-ctl 1.30.1 (bản đang dùng) chưa có option CLI --set-subdev-routing. Thử ioctl thủ công bằng Python cũng trả ENOTTY trên cả 3 subdev (csi2, pisp-fe, ov5647) — driver rp1-cfe hiện chưa expose ioctl này ra userspace theo cách tool có thể gọi trực tiếp.

❌ Lỗi 2 — ffmpeg: cùng nguyên nhân

output
[video4linux2,v4l2 @ 0x...] ioctl(VIDIOC_STREAMON): Invalid argument
[in#0 @ 0x...] Error opening input: Invalid argument
...
The V4L2 driver changed the pixel format from 0x32315559 to 0x41414270

ffmpeg thử nhiều format (YUYV, yuv420p...) nhưng driver luôn reset về Bayer format nội bộ (pBAA) — vẫn không stream được vì thiếu routing, không phải vì sai format.

❌ Lỗi 3 — VIDIOC_STREAMON: Broken pipe

Nguyên nhân: có 2 consumer cùng lúc tranh nhau 1 nguồn — link csi2 → pisp-fe vẫn đang ENABLED trong khi cố enable thêm csi2 → csi2_ch0. Không có routing table đúng, CSI2 không stream ra 2 nơi cùng lúc được.

bash
# Đúng thứ tự: disable link cũ TRƯỚC, enable link mới SAU
media-ctl -d /dev/media0 -l "'csi2':4->'pisp-fe':0[0]"          # disable trước
media-ctl -d /dev/media0 -l "'csi2':4->'rp1-cfe-csi2_ch0':0[1]"  # enable sau
Đây là giới hạn của driver mặc định, không phải phần cứng

Hành vi ENOTTY trên đúng với báo cáo từ cộng đồng RPi5 (kernel 6.18.x) tại thời điểm viết tài liệu này. Cần biết thêm: rp1-cfe có 2 biến thể — downstream (module rp1_cfe_downstream, mặc định trên Raspberry Pi OS, chỉ hỗ trợ multiplex 1 subdev/1 stream, không expose routing ioctl cho userspace) và upstream/mainline (module rp1_cfe, compatible string raspberrypi,rp1-cfe-upstream, đã nằm trong kernel mainline chính thức) đang tiếp tục phát triển hỗ trợ multiplexed streams đầy đủ hơn. Đây là trạng thái phát triển hiện tại, có thể thay đổi ở bản Raspberry Pi OS sau này — không nên coi là giới hạn vĩnh viễn của phần cứng.

07🔧 Đính chính: ffmpeg -f libcamera

❌ Thông tin sai trong tài liệu gốc Đã sửa

Bản gốc đề xuất ffmpeg -f libcamera -i ... như "Phương án A — có sẵn trên RPi OS". Qua tra cứu, đây không phải tính năng thật của FFmpeg mainline (kể cả bản build của Raspberry Pi OS). Danh sách input device chính thức của libavdevice (ffmpeg -devices) không có mục libcamera.

Một kỹ sư của Raspberry Pi Ltd (nick 6by9, thường xuyên trả lời kỹ thuật driver camera trên forum chính thức) xác nhận trực tiếp:

"Pi cameras now use libcamera. FFmpeg doesn't know how to drive libcamera, and tries various invalid things (eg VIDIOC_G_PARM) with the raw image sensor V4L2 devices, and hasn't configured the pipeline using Media Controller."

Nói cách khác: ffmpeg -f v4l2 -i /dev/video0 trên camera CSI RPi5 thất bại với đúng loại lỗi VIDIOC_STREAMON: Invalid argument đã ghi nhận ở mục 6 — vì cùng lý do (thiếu routing), và không có cờ -f libcamera nào để né việc này cả.

✅ Hai cách THẬT SỰ hoạt động

Cách 1 — Pipe từ rpicam-vid (khuyên dùng, verified rộng rãi)

bash
# rpicam-vid xuất raw/H264 ra stdout, ffmpeg nhận qua pipe — không đụng V4L2/libcamera trực tiếp
rpicam-vid -t 0 --codec yuv420 --width 1296 --height 972 -o - \
  | ffmpeg -f rawvideo -pixel_format yuv420p -video_size 1296x972 \
    -i - -frames:v 1 photo.jpg -y

# Hoặc lấy H264 đã encode sẵn (nhẹ CPU hơn, không cần re-encode)
rpicam-vid -t 10000 --codec h264 -o - \
  | ffmpeg -i - -c copy video.mp4

Cách 2 — libcamerify (V4L2 compatibility layer của chính libcamera)

bash
# libcamerify dùng LD_PRELOAD để "giả lập" device V4L2 thường,
# ffmpeg tưởng đang nói chuyện với /dev/video0 kiểu cũ, nhưng thực chất
# libcamera xử lý phía sau — không cần tự cấu hình Media Controller
sudo apt install libcamera-tools libcamera-v4l2

libcamerify ffmpeg -f v4l2 -i /dev/video0 -frames:v 1 photo.jpg -y
libcamerify v4l2-ctl --list-devices   # cũng dùng được với v4l2-ctl thường
⚠️ Lưu ý khi dùng libcamerify

Gói chứa v4l2-compat.so đã tách khỏi libcamera0 sang gói riêng libcamera-v4l2 từ Bookworm — thiếu gói này sẽ gặp lỗi object 'v4l2-compat.so' cannot be preloaded. Ngoài ra, cộng đồng RPi ghi nhận libcamerify + OpenCV có thêm độ trễ khoảng 1–2 giây so với gọi libcamera trực tiếp — không lý tưởng cho pipeline AI thời gian thực có ngân sách latency chặt. Với Python, picamera2 ở Phần 4 là lựa chọn nhanh hơn vì không đi qua lớp giả lập này.

Kết luận thực tế

Với camera CSI trên RPi5, libcamera là lớp bắt buộc phải đi qua — dù trực tiếp (rpicam-apps, picamera2), gián tiếp (GStreamer libcamerasrc), hay giả lập (libcamerify). Không có đường tắt V4L2 thuần nào tốt hơn ba cách này trên driver mặc định hiện tại.

09Lệnh tham khảo nhanh

bash
# USB camera — hoạt động ngay với mọi công cụ
ffmpeg -f v4l2 -video_size 1920x1080 -i /dev/video0 -frames:v 1 out.jpg -y

# CSI RPi5 — cách 1: pipe qua rpicam-vid
rpicam-vid -t 0 --codec yuv420 -o - | ffmpeg -f rawvideo \
  -pixel_format yuv420p -video_size 1296x972 -i - out.jpg -y

# CSI RPi5 — cách 2: libcamerify wrapper
libcamerify ffmpeg -f v4l2 -i /dev/video0 -frames:v 1 out.jpg -y

# CSI RPi5 — cách 3 (khuyên dùng cho AI/CV): picamera2, xem Phần 4
python3 -c "from picamera2 import Picamera2; p=Picamera2(); p.start(); print(p.capture_array('main').shape)"

# Trích metadata với ffprobe
ffprobe -v quiet -print_format json -show_streams input.mp4
