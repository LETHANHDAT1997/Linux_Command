1. D-Bus là gì?

D-Bus (Desktop Bus) là hệ thống IPC (Inter-Process Communication) tiêu chuẩn trên Linux, phát triển bởi freedesktop.org. Nó cho phép các process giao tiếp qua một message bus trung tâm theo mô hình service-oriented: client gọi method của remote object, nhận signal broadcast, đọc/ghi property — giống OOP nhưng xuyên ranh giới process.

1.1 So sánh với các cơ chế IPC khác

Unix SocketBidirectional, trên cùng hostPhải tự định nghĩa protocol, không có service discovery

1.2 D-Bus dùng để làm gì?

  • Service discovery: Tìm service theo well-known name (org.freedesktop.NetworkManager)
  • Remote Procedure Call: Gọi method của object trong process khác — sync hoặc async
  • Broadcast signals: Server phát event, tất cả subscriber nhận — không cần polling
  • Property access: Đọc/ghi thuộc tính qua standard interface org.freedesktop.DBus.Properties
  • Introspection: Khám phá API của service tại runtime qua XML
Context trong project JKC
Trong dự án JKC với Sigmastar SoC, D-Bus dùng để các daemon giao tiếp nhau: media daemon phát signal khi playback state thay đổi, power manager expose method để client yêu cầu shutdown, system monitor cung cấp properties về CPU/RAM. Tất cả qua System Bus — không cần mỗi daemon viết socket protocol riêng.

3. Các loại D-Bus

System Bus
Bus dùng chung toàn hệ thống. Mọi user và process truy cập cùng một instance duy nhất.
  • Socket: /run/dbus/system_bus_socket
  • Yêu cầu policy file (/etc/dbus-1/system.d/)
  • Dùng cho system services: NetworkManager, BlueZ, UPower…
  • Trong embedded: media daemon, power manager, CAN adapter…
Session Bus
Bus riêng cho mỗi user login session. Instance riêng cho từng user.
  • Socket: /run/user/<UID>/bus
  • Không cần policy file đặc biệt
  • Dùng trong desktop environment (GNOME, KDE…)
  • Tiện cho development & testing — không cần sudo
Peer-to-Peer (Direct)
Kết nối trực tiếp giữa hai process, không qua daemon.
  • Latency thấp hơn (bỏ qua broker hop)
  • Phù hợp embedded resource-constrained
  • Không có service discovery, không có broker
  • API: createDirectBusConnection()
Lựa chọn phù hợp cho Embedded Linux
Có systemd: System Bus là chuẩn. sdbus-cpp link vào libsystemd có sẵn.
Không có systemd (BusyBox init): Dùng SDBUSCPP_BUILD_LIBSYSTEMD=ON để sdbus-cpp tự bundle sd-bus static, hoặc dùng Peer-to-Peer bỏ qua hoàn toàn daemon.
Session Bus: Rất tiện khi dev & test trên máy desktop — không cần sudo hay policy file.

4.3 Các entity chính trong sdbus-cpp

IConnection
Kết nối đến D-Bus daemon. Chạy event loop. Nên share một instance cho nhiều objects/proxies.
IObject (Server)
Đại diện D-Bus object expose API. Đăng ký methods, signals, properties vào vtable. Emit signals.
IProxy (Client)
View của Object từ phía client. Gọi remote methods, subscribe signals, đọc/ghi properties.
sdbus::Variant
Container type-erased cho bất kỳ D-Bus type nào. Dùng trong properties và dict a{sv}.
sdbus::Error
Exception class mang error_name (dot-separated) và message. Server throw, client catch.
Slot (RAII)
Handle quản lý lifetime của signal subscription hoặc vtable registration. Destroy slot = unsubscribe tự động.

7. Ba tầng API của sdbus-cpp

① Basic API
  • Làm việc trực tiếp với D-Bus message objects
  • Manual serialize/deserialize với << / >>
  • Phải tự viết D-Bus signature strings ("ais")
  • Verbose, dễ sai runtime
  • Dùng để hiểu internals hoặc edge cases
② Convenience API
  • Method chaining: .callMethod().onInterface().withArguments()
  • Compiler tự deduce D-Bus signatures từ C++ types
  • Ngắn hơn, type-safe, zero runtime overhead
  • Nên dùng khi không cần codegen
③ Generated Bindings (sdbus-c++-xml2cpp)
  • Từ D-Bus XML IDL → generate header C++ (Adaptor + Proxy)
  • Remote calls trông như local C++ method calls
  • Adaptor: implement pure virtual methods cho server
  • Proxy: gọi method như member function cho client
  • Tầng cao nhất — dùng cho toàn bộ production service

9. Policy file (System Bus)

Policy file cho phép service đăng ký well-known name trên system bus. Không có file này, service sẽ bị từ chối với lỗi org.freedesktop.DBus.Error.AccessDenied.

Nếu bạn dùng Session Bus để test (khuyến nghị cho phát triển), bỏ qua bước này hoàn toàn.

<!-- Deploy: sudo cp policy/... /etc/dbus-1/system.d/ && sudo systemctl reload dbus -->

  "-//freedesktop//DTD D-BUS Bus Configuration 1.0//EN"
  "http://www.freedesktop.org/standards/dbus/1.0/busconfig.dtd">
<busconfig>
  <!-- User root được phép own (đăng ký) tên service này -->
  <policy user="root">
    <allow own="org.example.Concatenator"/>

  <policy context="default">
    <allow send_destination="org.example.Concatenator"/>
    <allow receive_sender="org.example.Concatenator"/>
  </policy>
</busconfig>

10. D-Bus XML IDL

File XML là contract giữa server và client. Nó định nghĩa tên, type signatures của tất cả methods, signals, properties. File này là input cho codegen tool.

<!-- dbus/org.example.Concatenator.xml -->
<?xml version="1.0" encoding="UTF-8"?>

<node name="/org/example/concatenator">
  <interface name="org.example.Concatenator">

    <!-- Method: nhận mảng số và separator, trả về chuỗi đã ghép -->
    <method name="Concatenate">
      <arg type="ai" name="numbers"   direction="in"/>  <!-- ai = array of int32 -->
      <arg type="s"  name="separator" direction="in"/>  <!--  s = string -->
      <arg type="s"  name="result"    direction="out"/> <!--  s = string return -->
    </method>

    <!-- Signal: phát sau mỗi lần Concatenate thành công -->
    <signal name="Concatenated">
      <arg type="s" name="result"/>
    </signal>

    <!-- Property: version string, read-only -->
    <property name="Version"      type="s" access="read"/>

    <!-- Property: số lần xử lý request, read-only -->
    <property name="RequestCount" type="u" access="read"/> <!-- u = uint32 -->

  </interface>
</node>

// FILE NÀY ĐƯỢC GENERATE TỰ ĐỘNG — không chỉnh sửa tay
#pragma once
#include <sdbus-c++/sdbus-c++.h>

namespace org::example {

class Concatenator_adaptor {
public:
    static constexpr const char* INTERFACE_NAME = "org.example.Concatenator";

protected:
    Concatenator_adaptor(sdbus::IObject& object) : m_object(object) {}

    void registerAdaptor() {
        m_object.addVTable(
          sdbus::registerMethod("Concatenate")
              .withInputParamNames("numbers", "separator")
              .withOutputParamNames("result")
              .implementedAs([this](
                  const std::vector<int32_t>& n,
                  const std::string& s) {
                      return this->Concatenate(n, s);
              }),
          sdbus::registerSignal("Concatenated")
              .withParameters<std::string>("result"),
          sdbus::registerProperty("Version")
              .withGetter([this](){ return this->Version(); }),
          sdbus::registerProperty("RequestCount")
              .withGetter([this](){ return this->RequestCount(); })
        ).forInterface(INTERFACE_NAME);
    }

    void unregisterAdaptor() { /* RAII cleanup */ }

public:
    // Helper để emit signal "Concatenated" từ subclass
    void emitConcatenated(const std::string& result) {
        m_object.emitSignal("Concatenated")
               .onInterface(INTERFACE_NAME)
               .withArguments(result);
    }

private:
    // Pure virtual: subclass phải override
    virtual std::string Concatenate(
        const std::vector<int32_t>&,
        const std::string&) = 0;
    virtual std::string Version() = 0;
    virtual uint32_t RequestCount() = 0;
    sdbus::IObject& m_object;
};

} // namespace org::example

src/Concatenator.cpp

#include "Concatenator.h"
#include <iostream>
#include <sstream>

Concatenator::Concatenator(sdbus::IConnection& connection,
                              sdbus::ObjectPath objectPath)
    : AdaptorInterfaces(connection, std::move(objectPath))
{
    // PHẢI gọi registerAdaptor() trong constructor:
    // → đăng ký vtable vào D-Bus daemon
    // → expose object với tất cả methods/signals/properties
    registerAdaptor();
    std::cout << "[Server] Object registered on D-Bus\n";
}

Concatenator::~Concatenator()
{
    // PHẢI gọi unregisterAdaptor() trong destructor:
    // → gỡ object khỏi D-Bus trước khi memory bị free
    // → tránh crash khi daemon gửi message sau khi object bị destroy
    unregisterAdaptor();
    std::cout << "[Server] Object unregistered\n";
}

std::string Concatenator::Concatenate(
    const std::vector<int32_t>& numbers,
    const std::string& separator)
{
    std::cout << "[Server] Concatenate(" << numbers.size()
              << " numbers, sep='" << separator << "')\n";

    if (numbers.empty()) {
        // Throw sdbus::Error → server gửi Error reply thay vì MethodReply
        // Error name phải theo định dạng "domain.Category.ErrorName"
        throw sdbus::Error(
            sdbus::Error::Name{"org.example.Concatenator.Error.EmptyInput"},
            "The numbers array must not be empty");
    }

    std::ostringstream oss;
    for (size_t i = 0; i < numbers.size(); ++i) {
        if (i > 0) oss << separator;
        oss << numbers[i];
    }
    std::string result = oss.str();

    m_requestCount++;

    // Emit signal dùng helper method được generate bởi xml2cpp
    emitConcatenated(result);

    std::cout << "[Server] Result: " << result << "\n";
    return result;
}

std::string Concatenator::Version() { return "1.0.0"; }

uint32_t Concatenator::RequestCount() { return m_requestCount.load(); }

src/main_server.cpp

#include <sdbus-c++/sdbus-c++.h>
#include "Concatenator.h"
#include <iostream>
#include <csignal>

sdbus::IConnection* g_connection = nullptr;

void onSignal(int sig) {
    std::cout << "\n[Server] Signal " << sig << " received, shutting down...\n";
    if (g_connection) g_connection->leaveEventLoop();
}

int main()
{
    // === BƯỚC 1: Tạo D-Bus connection và request well-known name ===
    // createSessionBusConnection → Session Bus (không cần sudo, không cần policy)
    // createSystemBusConnection  → System Bus (cần sudo + policy file)
    auto connection = sdbus::createSessionBusConnection(
        sdbus::ServiceName{"org.example.Concatenator"});
    g_connection = connection.get();

    // === BƯỚC 2: Tạo object và đăng ký API lên D-Bus ===
    // Constructor gọi registerAdaptor() → object visible trên bus ngay sau đây
    Concatenator concatenator(
        *connection,
        sdbus::ObjectPath{"/org/example/concatenator"});

    // === BƯỚC 3: Setup graceful shutdown ===
    std::signal(SIGINT,  onSignal);
    std::signal(SIGTERM, onSignal);

    std::cout << "[Server] Running on SESSION bus\n";
    std::cout << "[Server] Service: org.example.Concatenator\n";
    std::cout << "[Server] Object:  /org/example/concatenator\n";
    std::cout << "[Server] Press Ctrl+C to stop\n";

    // === BƯỚC 4: Vào event loop — block tại đây ===
    // Tất cả D-Bus messages được xử lý trong loop này
    // Khi leaveEventLoop() được gọi, hàm này return
    connection->enterEventLoop();

    // concatenator destructor → unregisterAdaptor() tự động gọi ở đây
    std::cout << "[Server] Shutdown complete\n";
    return 0;
}

16. Basic API Layer — Chi tiết

Cùng chức năng nhưng làm việc thủ công với D-Bus message objects. Phải tự viết signature strings và serialize/deserialize arguments.

// Server — Basic API: thấy rõ D-Bus messages
#include <sdbus-c++/sdbus-c++.h>

sdbus::IObject* g_obj = nullptr;

void onConcatenate(sdbus::MethodCall call)
{
    // Deserialize theo đúng thứ tự và đúng type như D-Bus signature "ais"
    std::vector<int32_t> numbers;
    call >> numbers;    // "ai" → vector<int32_t>

    std::string separator;
    call >> separator;  // "s" → string

    if (numbers.empty())
        throw sdbus::Error(
            sdbus::Error::Name{"org.example.Concatenator.Error.EmptyInput"},
            "Array must not be empty");

    std::string result;
    for (auto n : numbers)
        result += (result.empty() ? "" : separator) + std::to_string(n);

    // Tạo reply và serialize return value
    auto reply = call.createReply();
    reply << result;  // "s" → string
    reply.send();

    // Tạo và gửi signal thủ công
    auto sig = g_obj->createSignal(
        sdbus::InterfaceName{"org.example.Concatenator"},
        sdbus::SignalName{"Concatenated"});
    sig << result;
    g_obj->emitSignal(sig);
}

int main()
{
    auto conn = sdbus::createSessionBusConnection(
        sdbus::ServiceName{"org.example.Concatenator"});
    auto obj  = sdbus::createObject(*conn,
        sdbus::ObjectPath{"/org/example/concatenator"});
    g_obj = obj.get();

    // Phải viết signature strings thủ công: "ais" và "s"
    obj->addVTable(
        sdbus::MethodVTableItem{
            sdbus::MethodName{"Concatenate"},
            sdbus::Signature{"ais"},         // input sig
            {"numbers", "separator"},        // input names
            sdbus::Signature{"s"},           // output sig
            {"result"},                       // output names
            &onConcatenate, {}},
        sdbus::SignalVTableItem{
            sdbus::SignalName{"Concatenated"},
            sdbus::Signature{"s"}, {}, {}}
    ).forInterface("org.example.Concatenator");

    conn->enterEventLoop();
}

17. Convenience API Layer

Compiler tự deduce D-Bus type signatures từ C++ types tại compile-time. Không cần viết signature strings, không cần serialize thủ công. Code ngắn và an toàn hơn Basic API.

// Server — Convenience API
int main()
{
    auto conn = sdbus::createSessionBusConnection(
        sdbus::ServiceName{"org.example.Concatenator"});
    auto obj  = sdbus::createObject(*conn,
        sdbus::ObjectPath{"/org/example/concatenator"});

    auto doConcat = [&obj](
        const std::vector<int32_t>& numbers,
        const std::string& separator) -> std::string
    {
        if (numbers.empty())
            throw sdbus::Error(
                sdbus::Error::Name{"org.example.Concatenator.Error.EmptyInput"},
                "Array must not be empty");

        std::string result;
        for (size_t i = 0; i < numbers.size(); ++i)
            result += (i ? separator : "") + std::to_string(numbers[i]);

        // Emit signal — compiler deduce type "s" từ const string&
        obj->emitSignal("Concatenated")
              .onInterface("org.example.Concatenator")
              .withArguments(result);
        return result;
    };

    // Đăng ký vtable — không cần signature strings
    obj->addVTable(
        sdbus::registerMethod("Concatenate")
             .withInputParamNames("numbers", "separator")
             .withOutputParamNames("result")
             .implementedAs(std::move(doConcat)),
        sdbus::registerSignal("Concatenated")
             .withParameters<std::string>("result"),
        sdbus::registerProperty("Version")
             .withGetter([]() -> std::string { return "1.0.0"; })
    ).forInterface("org.example.Concatenator");

    conn->enterEventLoop();
}

20. Async Method Calls

20.1 Vấn đề: Tại sao cần Async?

Ở các section trước (17. Convenience API, 13. Client), khi client gọi method, code dùng callMethod() — đây là synchronous call: thread client bị block (đứng im) cho đến khi server xử lý xong và trả reply. Tương tự, khi server handler return, sdbus-cpp tự động gửi reply — nếu handler chạy lâu, event loop thread bị block, mọi request khác phải xếp hàng chờ.

Async method call giải quyết vấn đề này: client gửi request rồi tiếp tục chạy ngay, không chờ; server có thể hoãn reply mà không block event loop.

Hiểu đơn giản
Sync = gọi điện thoại: bạn phải đứng chờ người ta trả lời xong mới làm tiếp.
Async = gửi tin nhắn: bạn gửi xong làm việc khác, khi nào có reply thì đọc.

20.2 So sánh Sync vs Async

Tiêu chíSync (callMethod)Async (callMethodAsync)
Client threadBlock chờ replyGửi xong chạy tiếp ngay
Server handlerReturn = auto-reply, block event loopCó thể hoãn reply, giao cho thread khác xử lý
Nhận kết quảstoreResultsTo(result) — tại chỗQua callback (uponReplyInvoke) hoặc std::future
Error handlingtry/catch sdbus::Errorstd::optional<sdbus::Error> trong callback
Phù hợp khiMethod chạy nhanh, logic đơn giảnMethod chạy lâu, cần gọi nhiều method song song, UI thread không được block
Quan trọng
D-Bus message bên dưới hoàn toàn giống nhau: MethodCall → MethodReply. Async chỉ khác ở cách code C++ tổ chức việc chờ reply — thay vì block thread, nó dùng callback, future, hoặc hoãn reply phía server.

20.3 Timeline: Sync vs Async

═══ SYNC — client thread bị block ═══ Client thread: ──[gọi Concatenate()]──── [⏳ BLOCK CHỜ 2 giây] ────[nhận reply]──[tiếp tục]── Server event loop: ──[nhận call]──[xử lý 2 giây 🔴]──[auto-reply]──[nhận call tiếp]── ↑ trong 2 giây này, mọi request khác phải XẾP HÀNG CHỜ ═══ ASYNC (client callback) — client thread tự do ═══ Client thread: ──[gọi callMethodAsync()]──[tiếp tục làm việc khác ✅]────────────── Event loop thread: ──────────────────────────[nhận reply]──[gọi callback]────────────── ═══ ASYNC (server-side) — event loop server tự do ═══ Server event loop: ──[nhận call]──[spawn thread]──[return ngay ✅]──[nhận call tiếp]── Worker thread: ────────────────[xử lý 2 giây]──[returnResults() → reply client]──[end]

20.4 Client-side Async — Cách 1: Callback

Client gửi request rồi chạy tiếp ngay. Khi server trả reply, callback được gọi trên event loop thread. Dùng callMethodAsync() thay cho callMethod().

// ① GỬI request rồi CHẠY TIẾP NGAY — không chờ reply
proxy->callMethodAsync("Concatenate")
       .onInterface("org.example.Concatenator")
       .withArguments(std::vector<int32_t>{1,2,3}, std::string{":"})
       // ② Đăng ký callback — sẽ được gọi SAU khi reply đến
       .uponReplyInvoke([](std::optional<sdbus::Error> err,
                            const std::string& r) {
           // ③ Kiểm tra lỗi — async không throw exception,
           //    lỗi được truyền qua std::optional<Error>
           if (err) { std::cerr << err->getMessage(); return; }
           // ④ Xử lý kết quả khi reply thành công
           std::cout << "Async: " << r << "\n";
       });
// ⑤ Code ở đây chạy NGAY LẬP TỨC — không đợi server reply
std::cout << "Đã gửi request, đang làm việc khác...\n";

So sánh với sync
Sync: callMethod("X").withArguments(...).storeResultsTo(result) — block, lỗi qua try/catch.
Async: callMethodAsync("X").withArguments(...).uponReplyInvoke(callback) — không block, lỗi qua std::optional<Error> trong callback.

20.5 Client-side Async — Cách 2: std::future

Gửi request ngay, nhận std::future. Bạn có thể làm việc khác rồi gọi .get() khi thực sự cần kết quả — lúc đó mới block.

// ③ Khi THỰC SỰ CẦN kết quả — .get() sẽ block nếu reply chưa đến
//    Nếu reply đã đến rồi → .get() trả về ngay

Khi nào dùng Callback vs Future?
Callback: Khi bạn muốn xử lý reply hoàn toàn non-blocking (ví dụ: fire-and-forget, hoặc cập nhật UI khi có reply).
Future: Khi bạn muốn gửi nhiều request song song rồi chờ tất cả — giống Promise.all() trong JavaScript.

20.6 Server-side Async — Hoãn reply, không block event loop

Vấn đề với Sync Server

Ở sync server, khi handler return, sdbus-cpp tự động gửi reply. Nếu method chạy lâu (transcode video, query database), event loop thread bị block — toàn bộ D-Bus service đơ, không thể trả lời bất kỳ request nào khác.

// ❌ Sync server — BLOCK event loop 2 giây
sdbus::registerMethod("LongOperation")
     .implementedAs([](std::string input) -> std::string {
         std::this_thread::sleep_for(std::chrono::seconds(2));  // 🔴 block!
         return "Done: " + input;
         // return → sdbus auto-gửi reply
         // Trong 2 giây trên, KHÔNG có request nào khác được xử lý
     })
cpp

Giải pháp: Server-side Async

Dùng sdbus::Result<T> làm tham số đầu tiên + .markAsAsync(). Lambda handler spawn thread riêng để xử lý, rồi return ngay — event loop thread được giải phóng. Worker thread xử lý xong thì gọi returnResults() để gửi reply cho client.

// ✅ Async server — KHÔNG block event loop
obj->addVTable(
    sdbus::registerMethod("LongOperation")
         .implementedAs(
             [](sdbus::Result<std::string> result,  // ① "Hộp reply" — KHÔNG phải input từ client
                std::string input)                    //    input từ client bắt đầu từ đây
             {
                 // ② Tạo thread mới, MOVE hộp reply vào thread đó
                 //    std::move(result) = chuyển quyền sở hữu, lambda gốc không còn giữ
                 std::thread([r = std::move(result), input]() mutable {
                     // ③ Xử lý nặng trên thread riêng — KHÔNG phải event loop thread
                     std::this_thread::sleep_for(std::chrono::seconds(2));

                     // ④ Gửi reply cho client từ thread này
                     //    sdbus-cpp xử lý thread-safe — gọi từ bất kỳ thread nào
                     r.returnResults(std::string("Done: ") + input);

                     // Nếu muốn trả lỗi thay vì kết quả:
                     // r.returnError(sdbus::Error{...});

                 }).detach();  // ⑤ .detach() = "thả" thread, nó chạy độc lập
                                //    Sau detach, lambda RETURN NGAY → event loop tự do

                 // ⑥ Lambda return tại đây — KHÔNG chờ thread ở trên xong
                 //    Event loop thread được giải phóng, xử lý request tiếp
             })
         .markAsAsync()  // ⑦ BẮT BUỘC: báo sdbus "đừng auto-reply khi lambda return"
                        //    Nếu QUÊN → sdbus gửi reply rỗng ngay + thread gửi reply lần 2 → lỗi!
).forInterface("org.example.Service");

Ví dụ dùng std::thread(...).detach() cho đơn giản. Trong production, nên dùng thread pool thay vì tạo/hủy thread liên tục — đặc biệt trên embedded nơi tài nguyên hạn chế. Mỗi lần client gọi method = tạo 1 thread mới, gọi 100 lần = 100 thread → không scalable.

Ví dụ: Server-side Async với Thread Pool

Thay vì std::thread(...).detach() mỗi lần có request, tạo sẵn một pool gồm N worker threads. Các task được đẩy vào queue, worker thread nào rảnh thì lấy ra xử lý.

// ── ThreadPool đơn giản — tạo sẵn N threads, dùng lại cho mọi request ──
#include <thread>
#include <mutex>
#include <condition_variable>
#include <queue>
#include <functional>
#include <vector>

class ThreadPool {
public:
    // Tạo sẵn `count` worker threads — chạy suốt đời chương trình
    explicit ThreadPool(size_t count) : m_stop(false) {
        for (size_t i = 0; i < count; ++i) {
            m_workers.emplace_back([this]() {
                while (true) {
                    std::function<void()> task;
                    {   // ── lock scope ──
                        std::unique_lock lock(m_mtx);
                        // Chờ cho đến khi có task trong queue hoặc pool bị stop
                        m_cv.wait(lock, [this]{ return m_stop || !m_tasks.empty(); });
                        if (m_stop && m_tasks.empty()) return;
                        task = std::move(m_tasks.front());
                        m_tasks.pop();
                    }
                    task();  // Thực thi task ngoài lock
                }
            });
        }
    }

    // Đẩy task vào queue — worker thread rảnh sẽ lấy ra chạy
    void enqueue(std::function<void()> task) {
        {
            std::lock_guard lock(m_mtx);
            m_tasks.push(std::move(task));
        }
        m_cv.notify_one();  // Đánh thức 1 worker đang chờ
    }

    ~ThreadPool() {
        { std::lock_guard lock(m_mtx); m_stop = true; }
        m_cv.notify_all();
        for (auto& w : m_workers) w.join();  // Chờ tất cả workers xong
    }

private:
    std::vector<std::thread>            m_workers;
    std::queue<std::function<void()>>  m_tasks;
    std::mutex                          m_mtx;
    std::condition_variable             m_cv;
    bool                                m_stop;
};
cpp
// ── Sử dụng ThreadPool với server-side async ────────────────────────
int main() {
    auto conn = sdbus::createSessionBusConnection(
        sdbus::ServiceName{"org.example.Service"});
    auto obj  = sdbus::createObject(*conn,
        sdbus::ObjectPath{"/org/example/service"});

    // Tạo pool 4 threads — dùng chung cho MỌI async method
    ThreadPool pool(4);

    obj->addVTable(
        sdbus::registerMethod("LongOperation")
             .implementedAs(
                 // Capture &pool bằng reference — pool sống suốt đời main()
                 [&pool](sdbus::Result<std::string> result, std::string input) {
                     // Đẩy task vào pool — KHÔNG tạo thread mới
                     pool.enqueue([r = std::move(result), input]() mutable {
                         // Worker thread xử lý
                         std::this_thread::sleep_for(std::chrono::seconds(2));
                         r.returnResults(std::string("Done: ") + input);
                     });
                     // Lambda return ngay → event loop tự do
                 })
             .markAsAsync()
    ).forInterface("org.example.Service");

    conn->enterEventLoop();
    // pool destructor gọi join() tất cả workers khi main() kết thúc
}
cpp
So sánh detach vs thread pool
std::thread().detach(): Mỗi request tạo 1 thread mới → overhead tạo/hủy thread, không giới hạn số lượng, 100 requests đồng thời = 100 threads.
Thread pool: Tạo sẵn N threads, dùng lại cho mọi request → không overhead tạo/hủy, giới hạn concurrency. Nếu 100 requests đến cùng lúc với pool size 4 → 4 xử lý song song, 96 xếp hàng trong queue chờ.
Trên embedded (ví dụ: Sigmastar SoC 2-4 core), pool size 2-4 là hợp lý.
