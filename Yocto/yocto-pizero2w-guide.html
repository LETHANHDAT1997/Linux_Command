Embedded reference — Yocto / LVGL / FreeRTOS

Yocto cho Pi Zero 2W: LVGL + FreeRTOS (POSIX port)

Bản chi tiết, từng bước, có giải thích — dành cho người đã quen FreeRTOS/STM32 và Buildroot nhưng chưa từng đụng Yocto. Mục tiêu: viết app theo API FreeRTOS ngay từ đầu để sau này port sang MCU thật không phải viết lại logic, không phải để chạy real-time trên Pi.

00 · KIẾN TRÚC & KHÁI NIỆM

Yocto khác Buildroot ở chỗ nào

Buildroot bạn quen: 1 file cấu hình to (menuconfig kiểu kernel) cho toàn hệ thống, build tuần tự theo Makefile, output là 1 rootfs. Yocto chia nhỏ hơn nhiều: mỗi phần mềm là 1 recipe (file .bb), các recipe liên quan gom vào 1 layer (thư mục), và BitBake (công cụ build thật sự — "Yocto Project" là tên cả hệ sinh thái, không phải tên tool) tự tính recipe nào cần recipe nào, build đúng thứ tự, cache kết quả từng recipe riêng lẻ. Linh hoạt hơn Buildroot nhiều nhưng cũng có đường cong học tập dốc hơn.

layer
Thư mục chứa nhiều recipe liên quan — vd meta-raspberrypi = mọi thứ riêng cho board Raspberry Pi (kernel, bootloader, machine config).
recipe (.bb)
1 file mô tả cách lấy source (biến SRC_URI), build, cài đặt 1 phần mềm — tương đương 1 "package" trong Buildroot nhưng chi tiết/tuỳ biến được nhiều hơn.
.bbappend
File "vá thêm" vào 1 recipe có sẵn của layer khác mà không sửa trực tiếp file gốc — cách chuẩn để tuỳ biến mà không đụng vào source layer người khác viết.
MACHINE
Biến chọn board target, đặt trong local.conf — vai trò tương đương việc chọn board trong Buildroot, nhưng ở Yocto nó chỉ là 1 dòng biến, không phải cả 1 lần chạy menuconfig.
image recipe
1 loại recipe đặc biệt liệt kê tập hợp package nào sẽ có trong rootfs cuối — vd core-image-minimal.
local.conf / bblayers.conf
2 file cấu hình riêng cho mỗi thư mục build — local.conf chứa setting build (MACHINE, package cần thêm...), bblayers.conf liệt kê layer nào đang bật. Khác Buildroot: Yocto tách hẳn "code/recipe" (nằm trong git layer, dùng chung nhiều máy) khỏi "cấu hình build cụ thể của bạn" (nằm riêng trong thư mục build, không commit chung với layer).
Yocto Linux — Pi Zero 2W FreeRTOS POSIX port · LVGL fbdev
→sau này
port sang
MCU thật (STM32/ESP32...) FreeRTOS port thật · display driver SPI

Cả FreeRTOS lẫn LVGL đều có port chạy như 1 app userspace bình thường trên Linux, không cần bare-metal, không cần real-time:

  • FreeRTOS POSIX/Linux port (portable/ThirdParty/GCC/Posix trong repo FreeRTOS-Kernel chính thức) — dùng pthread + signal giả lập tick/context-switch. Tài liệu FreeRTOS nói rõ đây là simulator, không có real-time — đúng như bạn đã biết, dùng để phát triển/test logic task trước khi lên phần cứng thật.
  • LVGL trên Linux (lvgl/lv_port_linux) — cùng 1 codebase chạy được cả SDL2 (giả lập cửa sổ trên PC, code nhanh) lẫn fbdev/DRM (chạy thật trên màn hình gắn vào Pi), chỉ đổi driver.

Yocto ở đây không cần lo real-time hay kernel patch — chỉ cần thêm thư viện/recipe cho LVGL, vendor thêm source FreeRTOS-Kernel, rồi viết 1 app recipe nối chúng lại. Các bước dưới đây đi theo đúng thứ tự nên làm: dựng Yocto cơ bản trước → xác nhận chạy được → mới thêm LVGL → code app trên PC cho nhanh → cuối cùng mới đóng gói lên target thật.

02 · CHUẨN BỊ MÁY HOST

Máy build cần gì

1
Hệ điều hành

Ubuntu 22.04/24.04 64-bit (hoặc Debian gần đây) — đây là môi trường được Yocto test kỹ nhất. Máy ảo cũng chạy được, miễn đủ tài nguyên bên dưới.

2
Cài package cần thiết

Danh sách chính thức cho nhánh Scarthgap:

host 
sudo apt update
sudo apt install gawk wget git diffstat unzip texinfo gcc build-essential chrpath \
    socat cpio python3 python3-pip python3-pexpect xz-utils debianutils \
    iputils-ping python3-git python3-jinja2 python3-subunit zstd liblz4-tool \
    file locales libacl1
sudo locale-gen en_US.UTF-8
3
Dung lượng ổ đĩa

Chuẩn bị tối thiểu ~100GB trống. Yocto build lại toàn bộ toolchain (gcc, glibc...) và hàng trăm package từ source — tốn dung lượng hơn Buildroot rất nhiều, vì Buildroot thường build 1 lần rồi xong, còn Yocto giữ cache (sstate-cache) của từng recipe để build lại nhanh hơn lần sau.

4
RAM & thời gian

Càng nhiều RAM/core CPU, BitBake càng build song song được nhiều recipe cùng lúc — khuyên ≥8GB RAM, lý tưởng 16GB+. Lần build đầu tiên có thể mất 1–3+ tiếng tuỳ máy vì phải dựng lại toàn bộ toolchain từ đầu — đây là bình thường, không phải bị treo máy.

03 · TẢI POKY + LAYER

Poky là gì, và 3 layer cần

Poky không phải "1 tool" — nó là 1 "distro tham khảo" đóng gói sẵn: BitBake (công cụ build) + openembedded-core (recipe nền tảng: glibc, busybox, kernel chung...) + layer mặc định (meta-poky). Bạn không tự viết những thứ này, chỉ clone về dùng.

1
Clone 3 layer
host 
mkdir -p ~/yocto && cd ~/yocto
git clone -b scarthgap https://git.yoctoproject.org/poky
git clone -b scarthgap https://git.openembedded.org/meta-openembedded
git clone -b scarthgap https://github.com/agherzan/meta-raspberrypi

Scarthgap (5.0 LTS, hỗ trợ tới 04/2028) là bản ổn định nên dùng — recipe LVGL trong meta-openembedded đã chạy tốt trên nhánh này.

2
3 layer này làm gì
LayerVai trò
pokyBitBake + recipe nền tảng (glibc, busybox, kernel chung, toolchain)
meta-openembeddedKho recipe cộng đồng khổng lồ — recipe lvgl nằm trong sub-layer meta-oe của nó
meta-raspberrypiBSP layer — kernel/bootloader/machine-config riêng cho board Raspberry Pi, định nghĩa MACHINE = "raspberrypi0-2w"
04 · BUILD ẢNH ĐẦU TIÊN

Xác nhận setup đúng trước khi thêm gì khác

Nên build 1 ảnh tối thiểu trước, chưa vội thêm LVGL/FreeRTOS — để biết chắc layer/MACHINE/toolchain đều đúng, tránh vừa debug Yocto vừa debug LVGL cùng lúc.

1
Tạo build directory
host — trong ~/yocto 
source poky/oe-init-build-env build

Script này làm 3 việc: set biến môi trường trỏ vào bitbake, tạo thư mục build/ nếu chưa có (kèm 2 file mẫu conf/local.conf và conf/bblayers.conf), rồi tự cd vào đó. Từ giờ mọi lệnh bitbake chạy trong thư mục build/ này.

2
Bật 2 layer vừa clone
host — trong thư mục build 
bitbake-layers add-layer ../meta-openembedded/meta-oe
bitbake-layers add-layer ../meta-raspberrypi

Lệnh này chỉ đơn giản thêm 1 dòng đường dẫn vào file build/conf/bblayers.conf — mở file đó lên xem sẽ thấy. Có thể tự sửa tay file này cũng được, add-layer chỉ tránh gõ sai đường dẫn.

3
Chọn board

Mở build/conf/local.conf, tìm dòng MACHINE ?= "qemux86-64" (giá trị mặc định), thêm dòng mới bên dưới để ghi đè:

build/conf/local.conf 
MACHINE = "raspberrypi0-2w"
4
Build
host 
bitbake core-image-minimal

core-image-minimal là 1 image recipe có sẵn trong openembedded-core — rootfs tối thiểu (busybox, init, không GUI). Đây là lúc mất 1–3+ tiếng như nói ở trên, vì build lại toàn bộ toolchain từ đầu.

5
Flash thử ra thẻ SD

Ảnh nằm ở tmp/deploy/images/raspberrypi0-2w/. Trước khi cắm thẻ SD, chạy lsblk để xem danh sách ổ đĩa hiện có; cắm thẻ vào, chạy lại lsblk — ổ mới xuất hiện chính là thẻ SD.

Cẩn thận /dev/sdX: chọn sai ổ đĩa ở bước này sẽ ghi đè nhầm lên ổ cứng máy host, mất dữ liệu. Luôn xác nhận lại bằng lsblk trước khi chạy lệnh dưới.
host 
bmaptool copy tmp/deploy/images/raspberrypi0-2w/core-image-minimal-raspberrypi0-2w.wic.bz2 /dev/sdX
6
Boot thử

Cắm thẻ vào Pi, gắn màn hình HDMI (hoặc cáp UART-TTL vào 2 chân debug UART trên header GPIO), cấp nguồn. Thấy log kernel chạy qua rồi tới prompt đăng nhập (root, không cần mật khẩu mặc định) nghĩa là toàn bộ setup layer/MACHINE/toolchain đã đúng — có thể yên tâm thêm LVGL ở bước sau.

05 · THÊM LVGL

Thêm thư viện LVGL vào rootfs

1
Thêm vào local.conf
build/conf/local.conf 
IMAGE_INSTALL:append = " lvgl"

:append (cú pháp mới của bitbake, trước đây là _append) nối thêm vào cuối giá trị hiện có của biến, khác với = là gán/ghi đè hoàn toàn. Luôn nhớ để dấu cách ở đầu chuỗi (" lvgl") — thiếu dấu cách, giá trị mới sẽ dính liền vào giá trị cũ thành 1 từ sai.

2
Build lại
host 
bitbake core-image-minimal

Lần này BitBake chỉ build thêm phần mới (nhờ sstate-cache của lần build trước) — nhanh hơn lần đầu rất nhiều, không phải dựng lại toolchain.

3
Kiểm tra đã có trong ảnh

Flash lại, boot lên, SSH hoặc qua serial console vào target rồi chạy:

target 
find / -iname "*lvgl*" 2>/dev/null
06 · CODE TRÊN PC TRƯỚC

Dựng LVGL + FreeRTOS trên PC, chưa cần Pi

Build lên target rồi flash SD mỗi lần sửa code sẽ rất chậm. Cả lv_port_linux lẫn FreeRTOS POSIX port đều chạy thẳng trên PC Linux của bạn — code, chạy, sửa ngay tại đây, cuối cùng mới đóng gói qua Yocto.

LVGL: dựng lv_port_linux với driver SDL2

1
Clone + lấy LVGL (submodule)
PC (không phải target) 
git clone https://github.com/lvgl/lv_port_linux.git
cd lv_port_linux/
git submodule update --init --recursive

LVGL core nằm ở 1 repo riêng (lvgl/lvgl); lv_port_linux kéo nó vào như git submodule — quen thuộc nếu bạn từng dùng thư viện ngoài qua git trên STM32.

2
Cài dependency (SDL2)
PC 
sudo apt install libsdl2-dev
3
Chọn driver SDL2, build

Thư mục configs/ có sẵn file cấu hình mẫu cho từng driver — kiểm tra tên chính xác trong đó (thường dạng sdl.defaults), rồi build:

PC 
cmake -B build -DCONFIG=sdl
cmake --build build -j$(nproc)
./build/bin/lvglsim

Nếu chạy đúng, 1 cửa sổ demo LVGL sẽ hiện lên. Biến môi trường LV_SIM_WINDOW_WIDTH/LV_SIM_WINDOW_HEIGHT chỉnh kích thước cửa sổ giả lập nếu cần khớp với màn hình thật sau này.

FreeRTOS: thêm POSIX port vào cùng project

4
Clone FreeRTOS-Kernel
PC 
cd ..
git clone https://github.com/FreeRTOS/FreeRTOS-Kernel.git

Cấu trúc quan trọng cần biết:

Đường dẫnNội dung
tasks.c, queue.c, list.c...Lõi FreeRTOS — không đổi theo platform, giống hệt code bạn đã dùng trên STM32
portable/ThirdParty/GCC/Posix/"Port layer" cho Linux — phần duy nhất sẽ đổi khi lên MCU thật
FreeRTOSConfig.hKhông có sẵn — mỗi project tự viết (heap size, số priority, tick rate...), giống file bạn đã viết cho project STM32
5
Task LVGL đầu tiên

Cấu trúc app tối thiểu — 1 task lo vẽ LVGL, gọi đúng hàm quen thuộc xTaskCreate/vTaskStartScheduler:

main.c 
#include "FreeRTOS.h"
#include "task.h"
#include "lvgl.h"

void lvgl_task(void *pv) {
    lv_init();
    /* TODO: init driver hiển thị — SDL lúc dev, fbdev lúc lên target */
    for (;;) {
        lv_timer_handler();
        vTaskDelay(pdMS_TO_TICKS(5));
    }
}

int main(void) {
    xTaskCreate(lvgl_task, "lvgl", 8192, NULL, tskIDLE_PRIORITY + 1, NULL);
    vTaskStartScheduler();   /* không return nếu chạy đúng */
    for (;;);
}

xTaskCreate đăng ký task — cú pháp giống hệt bên STM32. vTaskStartScheduler() giao quyền điều khiển cho FreeRTOS: trên STM32 nó cấu hình SysTick + PendSV; trên port Posix nó tạo pthread + signal để giả lập tick. Code ở tầng application (task, priority, delay) không đổi giữa 2 môi trường — đây chính là điểm mấu chốt cho việc portability sau này.

Cần link thêm: port Posix cần pthread và rt — thêm target_link_libraries(app pthread rt) trong CMakeLists.txt của app.
Đúng như bạn đã biết: tài liệu chính thức của port POSIX nói rõ đây chỉ là simulator/emulation — Linux không chạy các thread giả lập liên tục nên số liệu thời gian không có ý nghĩa thực. Dùng để phát triển/test logic task và API portability, không phải để đo hiệu năng.
07 · ĐÓNG GÓI

Biến app đã chạy trên PC thành 1 Yocto recipe

Khi code đã chạy ổn trên PC, đóng gói thành recipe để Yocto build nó cho đúng kiến trúc CPU của Pi (cross-compile) và đưa vào rootfs.

1
Tạo layer riêng cho app
host — trong thư mục build 
bitbake-layers create-layer ../meta-mylvglapp
bitbake-layers add-layer ../meta-mylvglapp

Luôn tạo layer riêng cho code của mình, không sửa trực tiếp vào meta-openembedded hay meta-raspberrypi — 2 layer đó là code người khác viết, sẽ bị ghi đè nếu sau này bạn git pull cập nhật chúng.

2
Viết file recipe .bb
meta-mylvglapp/recipes-myapp/lvgl-rtos-app/lvgl-rtos-app_1.0.bb 
SUMMARY = "LVGL UI chay tren FreeRTOS POSIX port"
LICENSE = "MIT"
LIC_FILES_CHKSUM = "file://LICENSE;md5=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"

SRC_URI = " \
    git://github.com/YOUR_ORG/myapp.git;protocol=https;branch=main;name=app \
    git://github.com/FreeRTOS/FreeRTOS-Kernel.git;protocol=https;branch=main;destsuffix=git/FreeRTOS-Kernel;name=freertos \
"
SRCREV_app = "..."
SRCREV_freertos = "..."

DEPENDS = "lvgl"
S = "${WORKDIR}/git"

inherit cmake

Giải thích từng dòng:

DòngÝ nghĩa
SUMMARY / LICENSEMô tả ngắn + giấy phép — bắt buộc phải khai, Yocto dùng để sinh báo cáo license cho cả image lúc cần
LIC_FILES_CHKSUMChecksum MD5 của file LICENSE trong source — Yocto dùng để phát hiện khi nội dung license đổi giữa các lần fetch, tránh âm thầm đổi điều khoản pháp lý mà không ai để ý
SRC_URIKhai 2 nguồn git cùng lúc (app + FreeRTOS-Kernel), mỗi nguồn có name= riêng để tham chiếu SRCREV theo tên đó
SRCREV_<name>Commit hash cụ thể muốn build — ghim phiên bản, tránh build ra kết quả khác nhau mỗi lần tuỳ vào trạng thái mới nhất trên GitHub
DEPENDSRecipe khác cần build xong trước — ở đây cần lvgl (đã add ở bước 04) build trước để có header/thư viện dùng khi biên dịch app
inherit cmakeNạp sẵn toàn bộ logic build bằng CMake — tự động lo cross-compile toolchain cho đúng CPU của Pi, bạn không cần tự cấu hình toolchain file như khi build tay trên PC
MD5 thật: giá trị xxxx... ở trên chỉ là chỗ trống — lần đầu build, bitbake sẽ báo lỗi và in ra đúng giá trị MD5 thật của file LICENSE, copy giá trị đó vào là xong.
3
CMakeLists.txt của app

Trỏ nguồn tới cả 3 phần: code app, LVGL (đã có sẵn qua DEPENDS), và FreeRTOS-Kernel (nằm cạnh trong FreeRTOS-Kernel/ sau khi fetch nhờ destsuffix ở SRC_URI):

CMakeLists.txt (rút gọn) 
add_executable(myapp
    main.c
    FreeRTOS-Kernel/tasks.c
    FreeRTOS-Kernel/queue.c
    FreeRTOS-Kernel/list.c
    FreeRTOS-Kernel/portable/ThirdParty/GCC/Posix/port.c
    FreeRTOS-Kernel/portable/MemMang/heap_4.c
)
target_include_directories(myapp PRIVATE
    FreeRTOS-Kernel/include
    FreeRTOS-Kernel/portable/ThirdParty/GCC/Posix
    .   # noi chua FreeRTOSConfig.h
)
target_link_libraries(myapp PRIVATE lvgl pthread rt)
4
Thêm vào ảnh, build
build/conf/local.conf 
IMAGE_INSTALL:append = " lvgl-rtos-app"
host 
bitbake core-image-minimal
08 · TỰ ĐỘNG CHẠY

Chạy app lúc boot bằng systemd

1
Viết file .service
meta-mylvglapp/recipes-myapp/lvgl-rtos-app/files/lvglapp.service 
[Unit]
Description=LVGL RTOS App

[Service]
ExecStart=/usr/bin/myapp

[Install]
WantedBy=multi-user.target
2
Khai trong recipe

Thêm vào cuối file .bb:

lvgl-rtos-app_1.0.bb (thêm vào) 
inherit systemd
SRC_URI += "file://lvglapp.service"
SYSTEMD_SERVICE:${PN} = "lvglapp.service"

do_install:append() {
    install -d ${D}${systemd_system_unitdir}
    install -m 0644 ${WORKDIR}/lvglapp.service ${D}${systemd_system_unitdir}
}

inherit systemd nạp logic có sẵn để tự động enable service lúc build image (không cần tự chạy systemctl enable tay trên target). ${PN} là biến bitbake tự thay bằng tên package (lvgl-rtos-app) — quy ước chuẩn thay vì gõ cứng tên.

3
Quyền truy cập framebuffer

Mặc định user thường không có quyền ghi /dev/fb0. Nếu service không chạy bằng root, thêm dòng sau vào .service:

lvglapp.service (thêm vào [Service]) 
SupplementaryGroups=video

Trong CMakeLists.txt (hoặc file cấu hình LVGL), tắt LV_USE_SDL, bật LV_USE_LINUX_FBDEV — đây là chỗ duy nhất đổi giữa bản chạy trên PC và bản chạy trên Pi thật, phần code task/logic LVGL còn lại giữ nguyên.

host

3

target 
systemctl status lvglapp.service

Nếu màn hình gắn vào Pi hiện đúng UI đã thấy trên PC lúc dev — toàn bộ chuỗi Yocto → LVGL → FreeRTOS đã chạy đúng.
